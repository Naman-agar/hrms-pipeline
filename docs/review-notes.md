## TPRD 03 — user management

- `src/users/users.service.ts` §8 step 2 (DELETE): TPRD says "Last **active** HR Admin → 409 LAST_ADMIN", but the shared `assertNotLastAdmin` helper (built for §7, which has no `active` qualifier on the target) blocks deleting ANY HR Admin target — including an already inactive/suspended one — whenever no *other* active admin exists. Slightly over-restrictive for §8's literal wording; edge case only, user's call whether to special-case it.
- `src/users/users.service.ts` §6 step 2 (POST /users): email uniqueness is checked via pre-select (`findUnique`) per the TPRD's own step order, so a concurrent duplicate-email insert surfaces as Prisma `P2002` → 500 INTERNAL instead of 409 EMAIL_TAKEN. Matches the TPRD as written; catching `P2002` → EMAIL_TAKEN (as roles/departments already do) would be cheap extra hardening if the user wants it.
- `src/users/users.service.ts:119` — comment calling the §5 `GET /users/{id}` lookup "a single query" is inaccurate (role/department/invitations/`_count` are separate SELECTs under Prisma's default relation strategy, same reason as the AC-U11 `relationLoadStrategy` fix). Comment-only, no behavior issue.
- `src/prisma/prisma.service.ts`: query-event logging (`log: [{ emit: 'event', level: 'query' }]`, added for the AC-U11 fix) is always enabled, including in production, even with no subscriber — small per-query overhead. Could be gated by config/env later if it matters.
